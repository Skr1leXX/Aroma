# Демонстрация Aroma

Aroma — **вымышленный ресторан**. Все данные в проекте демонстрационные: названия, цены, отзывы, имена гостей
(`+7 (900) 000-00-xx`, `@example.com`) и фотографии блюд придуманы или взяты с Unsplash.

> **Что здесь не работает по-настоящему.** Заявки на бронирование и сообщения из контактной формы сохраняются в базе
> данных и видны в админ-панели, но **письма и SMS не отправляются** — провайдеры не подключены. Онлайн-оплаты нет.
> Письмо для сброса пароля в production не уходит (в разработке ссылка печатается в консоль сервера).

## Два способа показать проект

### A. Полностью локально, без внешних сервисов (5 минут)

Нужен только Node.js 20.9+. Поднимается настоящий PostgreSQL (пакет `embedded-postgres`), загружаются демо-данные,
а «Cloudinary» заменяется локальной заглушкой (загруженные фото будут пустыми пикселями — для проверки потока этого достаточно).

```bash
npm install
npm run demo:backends        # терминал 1: PostgreSQL :54329 + заглушка Cloudinary :54330, ждите строку READY
```

```bash
# терминал 2 (bash). В PowerShell: $env:ИМЯ="значение"
export DB_DRIVER=pg DEMO_MODE=true
export DATABASE_URL="postgresql://postgres:postgres@127.0.0.1:54329/aroma_test"
export BETTER_AUTH_SECRET="local-demo-secret-0123456789abcdef0123456789"
export BETTER_AUTH_URL="http://localhost:3000"
export CLOUDINARY_CLOUD_NAME=demo CLOUDINARY_API_KEY=demo CLOUDINARY_API_SECRET=demo
export CLOUDINARY_URL="cloudinary://demo:demo@demo?upload_prefix=http://127.0.0.1:54330"
export CLOUDINARY_UPLOAD_PREFIX="http://127.0.0.1:54330"
npm run dev
```

Тестовые учётные записи существуют **только** в этой временной локальной базе:

| Роль | Email | Пароль |
| --- | --- | --- |
| Администратор | `admin@aroma.test` | `admin-password-123` |
| Гость | `guest@aroma.test` | `guest-password-123` |

### B. На Neon + Cloudinary (как в production)

Следуйте разделам «Neon», «Cloudinary» и «Vercel» в [README](../README.md), затем создайте администратора:

```bash
ADMIN_EMAIL=demo-admin@example.com ADMIN_PASSWORD='придумайте-длинный-пароль' npm run admin:create
```

Пароль нигде не хранится в репозитории: вы задаёте его сами.

## Сценарий демонстрации (10–15 минут)

1. **Главная** `/` — hero, популярные блюда, отзывы (только опубликованные), контакты.
2. **Меню** `/menu` — фильтр по категориям, поиск («песто»), пустой результат («стейк» в десертах).
   Блюдо «Боул с лососем» отключено в админке, поэтому его нет ни в списке, ни по прямой ссылке (404).
3. **Карточка блюда** — состав, вес, аллергены, похожие блюда.
4. **Бронирование** `/reservation`
   - отправьте пустую форму — увидите ошибки по каждому полю;
   - выберите дату и число гостей — появятся **только свободные** интервалы;
   - после отправки — страница «Заявка принята», статус *ожидает подтверждения* (автоподтверждение выключено).
5. **Админ-панель** `/admin` (войдите администратором)
   - **Dashboard** — числа и график считаются по данным БД;
   - **Бронирования** — найдите заявку из шага 4 по имени/телефону → «Открыть» → *Подтвердить*, *Перенести*, оставить комментарий;
   - **Меню** — создайте блюдо, загрузите фото, отредактируйте, отключите, удалите (с подтверждением);
   - **Категории** — создайте, измените порядок; категорию с блюдами удалить нельзя;
   - **Галерея** — загрузка, замена, главное фото, порядок;
   - **Отзывы** — опубликовать/скрыть, рейтинг;
   - **Настройки** — телефон, график, лимиты бронирования, соцсети; изменения сразу видны в подвале сайта;
   - **Журнал** — каждое изменение записано (кто, когда, что изменилось).
6. **Права доступа** — выйдите; `/admin` ведёт на `/login`. Зарегистрируйте обычного пользователя: он видит только
   `/account`, а `/admin` возвращает его на главную. Роль `admin` нельзя получить через регистрацию.

## Сброс демо-данных

Seed идемпотентен: `npm run db:seed` добавляет недостающее и ничего не дублирует. Чтобы начать с чистого листа,
пересоздайте базу Neon (или остановите `demo:backends` — локальная база временная).
